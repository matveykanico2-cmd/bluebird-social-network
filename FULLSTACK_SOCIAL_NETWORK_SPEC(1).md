## 0. Главная команда разработчику

Создай с нуля полноценную самостоятельную социальную сеть по этому техническому заданию. Реализуй весь frontend, backend, API, базу данных, медиа, realtime, мобильные и desktop оболочки. Не ограничивайся прототипом или планом. Работай автономно в рамках одного запроса до исчерпания доступных ресурсов; не жди подтверждения для обычных безопасных действий. Не выполняй платные или необратимые внешние действия без разрешения. Используй собственное название и логотип.

**Обязательно редактируй этот файл по мере выполнения:** меняй `- [ ]` на `- [x]` только после реализации и успешного тестирования соответствующего пункта. Незавершённые и заблокированные пункты оставляй `[ ]`, указывай причину и следующий шаг в PROGRESS.md. Если строка содержит несколько возможностей, отметь её только после проверки всех. Веди FEATURE_MATRIX.md с путями к коду, API, таблицам и тестам; TEST_REPORT.md с командами и результатами. Не заявляй готовность без доказательств. После каждого этапа переходи к следующему.

## 1. Обязательный технологический стек

| Уровень | Обязательная основа |
|---|---|
| Monorepo | **npm workspaces**: `apps/*`, `packages/*` — не переводить весь проект на pnpm/Yarn без отдельного решения |
| Web | **React 19, TypeScript, Vite, React Router 8, TanStack Query, TanStack Virtual, CSS Modules** |
| Архитектура клиента | **Feature-Sliced Design (FSD 2.0)**: `app → views → widgets → features → entities → shared`; **`apps/web` — единственный frontend** |
| API | **NestJS 12 + TypeScript** на адаптере Express, расположение **`apps/api`** |
| API-модули | Nest-модули с `controller`, `service`, `repository`, Zod DTO/валидацией и guards |
| Данные | **SQLite + better-sqlite3 + Drizzle** с новой схемой, версионированными миграциями |
| Контракты | **Zod-схемы в `packages/shared`**; согласованные API-ответы и типы |
| Realtime | Авторизованный **WebSocket** , reconnect/backoff, доставка и синхронизация |
| Звонки | **WebRTC**, signaling; mesh-топология с возможностью перехода на SFU для масштабирования |
| Media | **sharp, FFmpeg, S3-compatible storage**, RTMP/media runtime; фоновые задачи и обработка медиа |
| Mobile | **Capacitor** и папки `android/`/native bridge, единая клиентская кодовая база |
| Desktop | **Tauri**, `src-tauri/`; native bridge |
| PWA/Push | Service Worker, Web Push/FCM, совместимость с системными уведомлениями |
| Testing | **Vitest, Testing Library, Playwright, contract tests** в `packages/contract-tests` |
| Запуск | `npm install`, `npm run dev` + `npm run dev:web`; production: `npm run build`, `npm run build:api`, `npm run start:nest` |

Создай современную архитектуру без legacy-слоя: controller → service → repository, Zod-контракты в packages/shared, FSD на клиенте. Node.js 22+. Создай все перечисленные npm scripts и .env.example. Не заменяй стек без согласования.

## 2. ЧТО СЧИТАЕТСЯ «ПОЛНОЦЕННЫЙ FULLSTACK»

Функция считается готовой, только если: (1) есть видимый и адаптивный UI; (2) существуют рабочие события/обработчики, а не декоративная кнопка; (3) добавлены необходимые API/WebSocket-события и Zod-контракты; (4) состояние надёжно хранится в БД/хранилище; (5) на сервере проверяются роли, владение и приватность; (6) предусмотрены ошибки, загрузка, пустые состояния и повторные запросы; (7) написаны релевантные тесты; (8) есть ручной сценарий воспроизведения; (9) нет регрессий; (10) обновлены документация и таблица готовности. Не заменять реализацию моковыми данными, фейковыми оплатами или заглушками.

Ниже — **максимально широкий каталог функций по аналогии с VK/ВКонтакте и его экосистемой**, включая пожелания к продукту, а не официальный и не гарантированно исчерпывающий перечень актуальных кнопок VK. Различай реально подтверждённые функции VK, желательные улучшения продукта и отдельные сервисы экосистемы. Учитывай лицензирование музыки, сторонних API и платежей.

## 8. ОБЯЗАТЕЛЬНЫЕ ПРОВЕРКИ И КРИТЕРИИ ПРИЁМКИ

- Реальный сценарий два/три аккаунта: регистрация → профиль → друзья/подписка → пост с медиа → коммент/реакция → репост → уведомление → личный чат → звонок → подписка на сообщество → клип/видео → просмотр в ленте. Всё сохраняется после перезапуска.
- Права доступа: чужой приватный пост не получить через UI/API/WS/прямую ссылку; блокировка действует во всех модулях; модератор не имеет прав владельца; поиск не раскрывает скрытые материалы.
- Медиа: upload, progress, resume/retry по продуктовой политике, обложка, воспроизведение, удаление и очистка; ошибки сети не повреждают данные.
- Realtime: события не приходят неавторизованным клиентам; after reconnect сообщения/уведомления не теряются и не дублируются.
- SQL data: миграции на чистой и заполненной тестовой БД; нет разрушительных сбросов `data/app.db`.
- Автоматизированные команды проекта: `npm run build:web`, `npm run build:api`, `npm run test:web`, `npm run test:api`, `npm run test:contract`, `npm run test:e2e`, `npm run test:types`, а также тесты прокси при изменениях. Учитывай фактическую настройку, не утверждай «всё прошло» без запуска.
- E2E скриншоты на 360, 390, 768, 1024, 1280, 1440, 1920, светлая/тёмная; клавиатура и screen reader; состояние offline, rate limit, expired session, upload failures.
- Production: Docker/PM2/HTTPS, health checks, log retention, backups/restore drill, security scan, мерки latency; полная документация по переменным окружения, без секретов и приватных ключей.
